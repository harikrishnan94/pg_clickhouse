## Reading
The two data-path copies Branch A paid on the consumer (fixed-width memcpy + String chars/offsets rebuild)
are **ELIMINATED** — proven by the −299 ms consumer user CPU on the String-heavy Q24 (B-it2) and by parity
on fixed-width. The **known residuals** (recorded, not buried): (1) the **kernel recv copy** — the DOMINANT
consumer cost, **~35% of consumer CPU** (`__arch_copy_to_user`, perf L0014; CB Q24 tcp − shm-adopt ≈ +240 ms),
host has no NIC header/data split (review §3) → the real-NIC north star, NOT closable on loopback; (2)
**Decimal128** alignment copy fallback (0 in the swept datasets); (3) the **Nullable null_map** transform
(n/a — non-Nullable producer). **The +7% arrow-vs-bespoke wall residual on the widest String cell is NOT any
single eliminable copy** — B-it3 proved it is NOT the decode (~0.4%), L0014 measured it is NOT wire size
(arrow `send_bytes` +0.7%) and NOT the serialize concat (~0.5% producer, B-it1); it is the distributed cost
of the standard Arrow framing (per-block metadata message + LargeBinary offsets-prepend + slightly more
recv-side bookkeeping), bounded to the widest cell — fixed-width is parity. **Send-side** (B-it4): io_uring
`IORING_OP_SEND` is the default; `MSG_ZEROCOPY` is a PROVEN loopback measured-NEGATIVE (deferred copy via
`SO_EE_CODE_ZEROCOPY_COPIED`, +7.3% slower) — a real-NIC-only elimination.
