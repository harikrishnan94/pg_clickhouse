Branch 0 — producer io_uring send is ON THE PATH (deterministic counter proof)
==============================================================================
Date: 2026-06-26. Host: AWS Graviton aarch64. pg_clickhouse + io_uring producer send.
DB: tpch_sf10, query TPC-H Q6 (lineitem 59,986,052 rows), tcp transport, 4 producer workers
(max_parallel_workers_per_gather=4). Instrument: per-producer send-path counter, emitted by the
worker's "shm tcp-send" LOG when pg_clickhouse.shm_log_stream_stats=on (src/shm_worker.c). This is a
DETERMINISTIC in-code counter — it counts exactly which send path each logical tcp_send_all() took,
removing the noise of system-wide syscall sampling.

A counter==send-path is unambiguous: io_uring_sends>0 && blocking_sends==0 proves the io_uring path
ran (not a silent fallback to blocking on a failed ring init).

Note on instrument selection (honest null): a first attempt used system-wide
`perf stat -a -e syscalls:sys_enter_io_uring_enter,sendto` for the query window. It was INCONCLUSIVE —
io_uring_enter ~1880 and sendto ~150 in BOTH runs — because the live ClickHouse server uses io_uring
for its own file reads (IOUringReader), swamping the producer's ~460 sends, and system-wide counts are
not attributable to the producer process. The per-producer counter above is the correct instrument.

Also note: `PGOPTIONS="-c pg_clickhouse.tcp_send_method=blocking"` did NOT take effect (the first
"blocking" attempt still logged method=io_uring) — a custom-GUC placeholder is not reliably converted
for a LOAD-time enum GUC. The selector works via an explicit `SET ...` after LOAD, which is exactly
what the sweep harness (wsweep_split.sh) emits, so the W=8 A/B is unaffected.

Correctness gate (io_uring default): verify_offload.sh TRANSPORT=tcp = 137/137 PASS (/tmp/b0_verify_iouring.log),
clean teardown (no leaked workers/sockets/fds). No new DIFF (bespoke wire unchanged).
