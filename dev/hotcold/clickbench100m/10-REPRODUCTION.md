## Split (D-HC-0403) — exact recency boundary on the UNIQUE 5-tuple
`(EventTime,WatchID,UserID,CounterID,EventDate)` is unique over the 99,997,497 rows. Recency order = all-DESC.
hot(f) = `tuple >= B(f)`, cold(f) = `tuple < B(f)`; B(f) (the N(f)-th most-recent row) in `boundaries.env`.
N(1%)=1,000,000 N(5%)=5,000,000 N(10%)=10,000,000. Verified EXACT (hot==N, hot+cold==TOTAL).

## Merge template (D-HC-0402) — single CH execution, no planner routing
1. Background producer (PG): streams the hot heap into a named SHM ring and waits for the CH consumer:
```
sudo -u postgres psql -d clickbench -X -q -c \
 "LOAD 'pg_clickhouse'; SET search_path=pg,public; SET statement_timeout='240s';
  SELECT clickhouse_stream_relation('pg.hits_hot_p<f>'::regclass, 'pgch_hot_p<f>', 65536);" &
# wait for /tmp/clickhouse_shm_pgch_hot_p<f>.sock
```
2. Merged query (CH HTTP), the per-query deparsed body with its single streamed_table source replaced by
   the hot∪cold subquery (generated by mk_merge_sql.py):
```
SELECT <body> FROM (SELECT * FROM (
    (SELECT <projcols> FROM streamed_table('pgch_hot_p<f>', '<FULL 105-col wire schema>'))
    UNION ALL
    (SELECT <projcols, cold-cast> FROM clickbench.hits_100m WHERE <tuple < B(f)>)
)) [WHERE..GROUP BY..ORDER BY..LIMIT]
```
   CH session settings (match the deparser's; identical for pure-CH and merge):
   `allow_experimental_streamed_table_function=1, join_use_nulls=1, group_by_use_nulls=1, final=1,
    count_distinct_implementation=uniqExact, max_bytes_before_external_group_by=4G, max_bytes_before_external_sort=4G`.

- pure-CH-100M baseline (ground truth): same body, source = `clickbench.hits_dt64`
  (a view = hits_100m with lowercase names + the 3 timestamps cast to DateTime64(6,'UTC')).

Generate either with: `python3 mk_merge_sql.py templates/q<q>.ch.sql {pure|p01|p05|p10}`.
